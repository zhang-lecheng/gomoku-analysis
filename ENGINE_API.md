# Rapfi worker interface

Create `new Worker('./engine-worker.js')`. Send `{type:'init', mode:'single', threads:1}` and wait for `ready`. When `crossOriginIsolated` is true, `{type:'init', mode:'multi', threads:2}` selects the pthread SIMD build (2–8 threads). Otherwise the worker reports `single` and one thread. The included service worker enables cross-origin isolation for HTTPS static hosting after a reload; startup continues in single-thread mode when unavailable. Both variants share one model data file. `ready` reports `version`, `model`, `mode`, `threads`, and `simd`. There is no heuristic fallback.

Send `{type:'analyze', id, moves, sideToMove, timeMs, multiPV, hashMB, maxDepth}`. `moves` is an array of `{x,y,color}` with zero-based coordinates, x left-to-right and y top-to-bottom. Black is 1, white is 2, and `sideToMove` is the physical color 1 or 2 (`side` is also accepted). `timeMs:0` sets a 24-hour ceiling. Values are bounded to 100 ms–24 h, 1–20 PVs, 16–1024 MB and an optional `maxDepth` of 2–99 (`0` or absent means no depth target). `maxDepth` is the primary stop condition; `timeMs` remains a cap. `INFO max_depth` persists inside the worker, so the adapter writes it on every analysis and restores the engine ceiling (99) when no target is given. `INFO max_node` is not used: Rapfi only consults `options.maxNodes` in its MCTS and opening-balance code, so it does not limit an alpha-beta search. The transposition table is cleared with `YXHASHCLEAR` before every `YXBOARD`, because `YXBOARD` rebuilds the position without resetting the hash. Rapfi's raw evaluation is from the side to move, in its own score units; it is not a probability. `winrate` is Rapfi's estimate for the side to move. A forced mate is emitted as `scoreType:'mate'` with signed `score` equal to Rapfi's displayed mate distance **in plies** (`M+35` is 35 plies, i.e. about 18 of the winner's moves — `VALUE_MATE - value` in `core/iohelper.cpp`); ordinary values have `scoreType:'eval'`. A mate score is a search-tree verdict, not an exhaustive proof.

Events: `status {message}`, `ready`, `log {message}`, `error {id,message}`, `pv {id,index,depth,selDepth,score,scoreType:'eval'|'mate',winrate,nodes,timeMs,nps,pv:[{x,y}]}`, `stats {id,depth,nodes,timeMs,nps}`, `done {id,move:{x,y}|null,reason:'depth'|'mate'|'time',depth}`. `reason` reports why the search ended: `depth` — the target depth was reached (device independent); `mate` — the engine stopped on its own after a mate distance settled; `time` — the wall-clock cap cut the search short, so the result depends on machine speed. `depth` on `done` is the last completed iteration. PV index starts at 1. All search events echo `id`. `MESSAGE` output is diagnostic and its algebraic labels use Rapfi's convention; use numeric coordinates only.

Single-thread search is synchronous within its worker: to stop immediately, call `worker.terminate()` and create and initialize a fresh worker. A `stop` message cannot interrupt a running search. A board is reordered into black-first, alternating rows when possible, preserving physical stone colors. Rapfi inserts passes for successive same-color rows, and the adapter adds a pass when needed to choose the requested side. Artificial passes can affect search history and therefore edited positions are not equivalent to a known game history. Normal legal histories alternate without inserted passes.
